## Git flow : récupérer sur son dépôt la mise à jour du code venant du prof

- Se déplacer sur notre machine dans le dépôt du projet
  - vérifier avec `pwd` qu'on est au bon endroit
  - vérifier avec `git remote -v` qu'on a bien la bonne adresse SSH

- Regarder sur quelle branche on est avec `git branch`
- Repartir sur votre branche principale `git checkout main OU master (en fonction)`
- Vérifier que vous avez bien changé de branche `git branch` - vous devriez voir * master OU main (en vert généralement)

- Connecter votre dépot au dépôt prof `git remote add prof git@github.com:O-clock-Figueres/SC01234-oquiz-guillaumeoclock.git`
- Si l'adresse remote a bien été rajoutée, on la vera en faisant un `git remote -v`

- On récupère les infos venant du depot distant prof `git fetch prof`
- On pull le contenu de la branche main du dépot prof, et par prévention, on fait en même temps un reset pour effacer d'eventuelles modifications locales `git reset --hard prof/main`
- Une fois qu'on a récupéré le contenu main du dépot prof (sous entendu, la correction du jour), on push ce qu'on a : `git push -f`

## Cloner le dépôt github sur notre vps

- On se reconnecte au serveur VPS /!\ (bien vérifier que notre prompt représente bien notre serveur)

Pour cloner notre dépôt, on a besoin d'être identifié par github, pour cela, on va générer une clé SSH, qu'on va ensuite copier dans l'interface github

- Générer la clé SSH `ssh-keygen -t ed25519 -C "your_email@example.com"`
  - 3 questions sont posées avant de générer la clé SSH, pour les 3: juste appuyer sur entrée (si on demande d'overwrite, écrire `y` et taper entrée)
- Une fois la clé SSH générée, on souhaite l'afficher dans notre terminal pour la copier : `cat /home/student/.ssh/id_ed25519.pub` (/!\ bien prendre la clé publique !)
- On va maintenant passer la clé SSH à notre dépôt, afin qu'on aie l'autorisation sur le serveur de cloner celui-ci (https://github.com/O-clock-Figueres/SC01234-oquiz-VOTREPSEUDO/settings/keys)
- Sur notre serveur : se placer dans le dossier courant : `cd ~` le "~" représente le dossier courant de votre environement, vous serez ensuite dans /home/student (à vérifier avec `pwd`)
- Puis cloner le dépot : `git clone git@github.com:VotreAdresseDeDepot`

## Installer docker

```
sudo apt update
sudo apt install ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
```


Une seule commande : 
```
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Signed-By: /etc/apt/keyrings/docker.asc
EOF
```

```
sudo apt update
```

```
sudo apt-get install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

Vérification : 

#### Setup une config pour nginx

- Modifier docker-compose.yml
On rajoute après client et api un nouveau volume : 
```
  proxy:
    image: nginx:alpine
    restart: unless-stopped
    volumes:
      - ./proxy/nginx.conf:/etc/nginx/conf.d/oquiz.conf
    ports:
      - 80:80
    depends_on:
      - api
      - client
    networks:
      - oquiz-network
```
- Créer le fichier de conf pour nginx
- Dans le projet, créer à la racine un dossier "proxy"
  - `mkdir proxy`
  - `cd proxy`
  - `nano nginx.conf`

écrire dans nginx.conf 

```
# Dans le dossier `proxy-service/nginx.conf`
# Puisque cette config utilise le serveur eddi.cloud, elle ne fonctionnera pas en local.
# Il faudrait aller une étape plus loin.

# Client
server {
    # PORT 80 : port par défaut de HTTP
    listen 80;

    # On écoute l'URL suivante
    server_name oquiz.PSEUDO-server.eddi.cloud;

    # Et on redirige les requêtes vers ce service
    location / {
  # le hostname du service est 'client' -> c'est le nom du conteneur dans le network 
        proxy_pass http://client:80;

        # Pour permettre le transfert des headers HTTP également
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# API
server {
    listen 80;
    server_name oquiz-api.PSEUDO-server.eddi.cloud;

    location / {
        proxy_pass http://api:3001;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

/!\ Penser à modifier pseudo, remplacer PSEUDO par votre pseudo de serveur
/!\ Penser à modifier l'adresse d'api, http://api:3000 , changer en http://api:3001 si c'est pas déjà fait
/!\ Si vous avez un problème avec depends-on, problème de typo, changer en "depends_on" dans le fichier docker-compose

- Une fois que la config a été rajoutée, on ferme nos containers : `docker compose -p oquiz down`
- On va relancer nos services pour que nginx soit pris en compte
- On va aussi supprimer l'ancienne image du client, parce que les variables de l'env ont changé `docker rmi oquiz-client`
- On supprime le volume docker `docker volume rm oquiz_oquiz-volume`
- On relance le build de nos containers : `docker compose -p oquiz -f docker-compose.yml --env-file=.env.docker up -d --build`
